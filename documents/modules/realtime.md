# Модуль `realtime`

**Отвечает за:** мгновенную доставку событий в браузер — новое в темах форума, по сущностям из
интересов, ответы на свои сообщения.
**URL:** `/ws` (WebSocket) · **Код:** `modules/realtime/`

**Статус:** ✅ WebSocket с каналами (`thread:`, `entity:`, `rooms`, `user:me`), гости и вошедшие, автоподписка
по интересам, продление входа без разрыва, лимиты и heartbeat. Шина — внутри процесса.
Каналы людей, тегов и своих комнат (`person:`, `tag:`, `room:`), автоподписка по интересам и
вступлению. Чат комнат сущностей, людей, тегов и своих комнат админа: отправка и «прочитано» по WebSocket (`chat.send`, `chat.read`), сообщения —
в каналы комнат. 🕓 Redis pub/sub для нескольких экземпляров приложения.

## Таблицы

Своих таблиц нет и не планируется. `realtime` — это транспорт: данные создают другие модули
(`social` сохраняет сообщение в БД) и публикуют событие, а `realtime` доставляет его подписанным
клиентам. В чужие таблицы не ходит: slug сущностей — через `state.entities`, интересы — через
`state.interests` (`shared::directory`).

## Как работает

```
пользователь пишет в тему ──► social: сохранить в БД, commit ──► state.events.publish(Event)
                                                                         │  (shared::events::EventBus)
                                                                         ▼
                                realtime: каждое соединение проверяет, подписано ли оно на каналы события
                                                                         │
                                                                         ▼
                                                    {"type":"event", ...} по открытым WebSocket'ам
```

- **Шина** — `shared::events::EventBus` в `AppState` (`tokio::sync::broadcast`, ёмкость 1024). Модули
  не вызывают `realtime` напрямую ([границы модулей](../architecture.md#правила-границ)): публикуют
  `Event { kind, channels, data }`, а каждое соединение `realtime` подписано на шину.
- **Один экземпляр приложения** — шины внутри процесса хватает. Когда экземпляров станет несколько,
  за тем же `EventBus` появится мост через Redis pub/sub, модули менять не придётся.
- **В событиях только id.** Тексты, имена, счётчики клиент перечитывает по REST API. Так событие не
  устаревает, не раскрывает удалённое и не обходит права (приватного в событиях нет).

## Протокол

JSON-сообщения с полем `type`. Соединение открывается **гостем**: для публичных каналов токен не
нужен (форум и так читается без входа).

### Клиент → сервер

| Сообщение | Что делает | Ответ |
|---|---|---|
| `{"type":"auth","token":"<access>"}` | Войти или продлить вход тем же пользователем | `authenticated` или `error` |
| `{"type":"subscribe","channels":["thread:<id>","entity:<slug>"]}` | Подписаться. Всё или ничего: при любой ошибке не подписывается ни на один | `subscribed` или `error` |
| `{"type":"unsubscribe","channels":[...]}` | Отписаться от каналов, подписанных вручную | `unsubscribed` |
| `{"type":"ping"}` | Проверка связи на уровне приложения | `pong` |
| `{"type":"chat.send","room":"entity:<slug>","body":"…","reply_to":null,"client_id":"tmp-1"}` | Сообщение в чат комнаты `entity:`, `person:`, `tag:` или `room:<slug>` (только после `auth`). Пишет `social` через `state.chat`; `reply_to`, `client_id` необязательны | `chat.sent` или `error` (с тем же `client_id`) |
| `{"type":"chat.read","room":"entity:<slug>","message_id":"…"}` | Прочитано в комнате до сообщения (только после `auth`) | `chat.read_saved` или `error` |

### Сервер → клиент

| Сообщение | Когда |
|---|---|
| `{"type":"authenticated","user_id":"…","expires_at":"…","channels":["user:me","entity:dune-2021",…]}` | После `auth`: `user:me` и каналы интересов подписаны сами |
| `{"type":"subscribed","channels":[…]}` / `{"type":"unsubscribed","channels":[…]}` | Ответ на подписку / отписку |
| `{"type":"event","event":"post.created","channels":["thread:…","entity:dune-2021"],"data":{…}}` | Событие. Подходит под несколько подписанных каналов — приходит **один раз**, в `channels` все совпавшие |
| `{"type":"auth_expiring","expires_at":"…"}` | За минуту до истечения токена (или сразу после `auth`, если осталось меньше) |
| `{"type":"auth_expired","channels":["user:me",…]}` | Токен истёк и не продлён: соединение стало гостевым, перечислены отключённые каналы |
| `{"type":"lagged","missed":17}` | Клиент не успевал читать, события пропущены: перечитайте открытые данные по API |
| `{"type":"error","error":"…"}` | Ошибка запроса; состояние соединения не меняется |
| `{"type":"pong"}` | Ответ на `ping` |
| `{"type":"chat.sent","client_id":"tmp-1","room":"entity:dune-2021","message":{…}}` | Сообщение записано; `message` — как в событии `chat.message.created` (его получат подписчики комнаты, в том числе другие соединения отправителя) |
| `{"type":"chat.read_saved","room":"…","message_id":"…"}` | Прочитанное сохранено; остальным соединениям пользователя — событие `chat.read` в `user:me` |
| `{"type":"error","error":"too many messages","retry_after":10,"client_id":"…"}` | Лимит частоты чата (5 сообщений за 10 с). Другие ошибки чата: `not authenticated`, `unknown chat room: …`, `unknown entity|person|tag|room in channel: …`, ошибки текста и `reply_to`, `not found` |

### Каналы

| Канал | Кто может | Что приходит |
|---|---|---|
| `thread:<id>` | все | Сообщения темы (создано, изменено, удалено), изменение, закрытие и удаление темы |
| `entity:<slug>` | все | Новые темы о сущности, сообщения в её темах, изменение и удаление этих тем, рецензии |
| `person:<slug>` | все | Чат комнаты человека (`chat.message.*`). Неизвестный или скрытый человек — `error` |
| `tag:<slug>` | все | Чат комнаты тега. Неизвестный тег — `error` |
| `room:<slug>` | все | Комната со slug (системная, админская или своя): чат, `chat.room.updated` / `chat.room.deleted`. Неизвестная — `error` |
| `dm:<id>` | только двое участников | Личная переписка: `chat.message.*`. Подписывается сама после `auth` и на лету по `dm.created`; чужая — `error` «unknown dm», гостю тоже |
| `rooms` | все, только вручную | Каталог комнат чата: `chat.room.created` (новая комната), а также `chat.room.updated` / `chat.room.deleted` — чтобы открытый список обновлялся без перезагрузки. Автоматически никому не выдаётся |
| `user:me` | только после `auth`, подписывается сам | `reply.created` — ответили на ваше сообщение; `interest.added` / `interest.removed`; `chat.mention` — вас назвали `@username` в чате; `dm.created` — с вами завели переписку |
| интересы | только после `auth`, подписываются сами | Как `entity:<slug>`, `person:<slug>`, `tag:<slug>`: по каждой сущности, человеку и тегу из интересов пользователя, своей комнате, в которую он вступил, и каждой системной комнате чата (в них состоят все) (`InterestDirectory::entity_ids`, `person_ids`, `tag_ids`, `room_ids`; slug комнат — `Chat::room_slugs`). `interest.added` / `interest.removed` с `entity_id`, `person_id`, `tag_id` или `room_id` меняют подписки на лету |

Существование темы при подписке не проверяется (realtime не читает таблицы форума): на
несуществующую тему просто не придёт событий. Неизвестная сущность — `error`.

**Интересы меняются на лету.** Пользователь добавил сущность в интересы (`PUT
/api/v1/social/entities/{slug}/interest`, с любого устройства) — во все его соединения приходит
`interest.added`, и соединения сами подписываются на эту сущность; `interest.removed` — отписываются.
`unsubscribe` каналы интересов не трогает: они меняются только через API интересов.

### События

Список и данные — в [social.md](social.md#события-для-realtime). Пример:

```json
{"type":"event","event":"post.created","channels":["thread:6f1c…"],
 "data":{"thread_id":"6f1c…","post_id":"9a02…","parent_id":null,"author_id":"00000000-…-0003"}}
```

### Срок токена: продление без разрыва

Access-токен живёт 15 минут, а соединение — часами. Чтобы клиент не терял подписки:

1. За минуту до истечения сервер присылает `auth_expiring`.
2. Клиент обновляет токен как обычно (`POST /api/v1/auth/refresh`) и присылает `{"type":"auth","token":"<новый>"}`
   в **то же** соединение. Подписки остаются, в ответ — `authenticated` с новым `expires_at`.
3. Не прислал — в момент истечения приходит `auth_expired`: `user:me` и каналы интересов отключены,
   подписки `thread:`/`entity:` остаются, соединение работает как гостевое. Новый `auth` всё вернёт.

`auth` другим пользователем в том же соединении — смена пользователя: личные каналы прежнего
отключаются. Как и в REST API, проверяются подпись и срок токена; выход из сессии (`logout`)
действует на соединение не позже, чем истечёт токен.

### Лимиты и heartbeat

| | |
|---|---|
| Каналов, подписанных вручную, на соединение | 200 (`user:me` и интересы не считаются) |
| Соединений одного пользователя | 5; шестой `auth` — `error`, соединение остаётся гостевым |
| Размер сообщения от клиента | 16 КБ |
| Ping от сервера | каждые 30 секунд (WebSocket ping, браузер отвечает сам) |
| Тишина от клиента | больше 60 секунд (ни сообщений, ни pong) — сервер закрывает соединение (код 1001) |
| Отставание | больше 1024 событий в очереди — `lagged` |

Константы — `modules/realtime/src/lib.rs`. nginx держит соединение до часа без трафика
(`proxy_read_timeout 3600s`), heartbeat не даёт ему закрыться раньше.

### Что делает клиент

- Открыл тему — `subscribe` на `thread:<id>`, ушёл — `unsubscribe`.
- На `event` — перечитать нужное по API (страницу темы, список тем сущности) или показать
  «есть новые сообщения».
- На `lagged` и после переподключения — перечитать открытые экраны: события, пропущенные за время
  разрыва, не повторяются.
- Разрыв соединения — переподключиться с паузой (1, 2, 4, … до 30 секунд), затем `auth` и
  `subscribe` заново.

## Код

| Файл | Что внутри |
|---|---|
| `lib.rs` | Роутер `/ws`, константы лимитов |
| `connection.rs` | Цикл соединения: сообщения клиента, события шины, heartbeat, срок токена |
| `channels.rs` | Имена каналов ↔ `shared::events::Channel` (`thread:`, `entity:`, `person:`, `tag:`, `room:`); каналы интересов (`interests`, `rooms`); комнаты чата (`chat_room`) |
| `registry.rs` | Счётчик соединений пользователя |

Шина — `libs/shared/src/events.rs`. Тесты — `app/tests/realtime.rs` и `app/tests/chat.rs` (чат): настоящий WebSocket против
приложения на случайном порту (клиент `tokio-tungstenite`). Ручная проверка — `http/realtime.http`
(в IDE; `make http` WebSocket не умеет).
