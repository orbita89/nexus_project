# Промпт для фронтенда: поиск только через Meilisearch и расширенные фильтры

Задача для сессии фронтенда (`/home/dev/nexus_web`). Бэкенд не менять: если в API чего-то не
хватает — записать в `docs/backend-questions.md`.

---

## Контекст

С 2026-10-14 **весь поиск на сайте идёт через Meilisearch** — `GET /api/v1/catalog/search`.
Публичный список `GET /entities` больше не ищет по названию: запрос с `q` отвечает
**400 `use_search`**. Сейчас так ломается страница `/films?q=...` (`src/routes/[kind=kind]/+page.ts`)
и запасной путь в `EntityPicker.svelte` (при 503 он идёт в `/entities?q=` — убрать, показывать
«поиск недоступен»).

Контракт — `documents/api/catalog.json` бэкенда (перегенерировать клиент:
`src/lib/api/generated/catalog.ts`). Ошибки — `{"error": "...", "code": "..."}`.

## API

### `GET /search` — без авторизации

| Параметр | Что делает |
|---|---|
| `q` | Название, оригинальное название, студии; опечатки допустимы. Пустой — все, кто подходит под фильтры |
| `kind` | `movie` / `series` / `book` / `game` |
| `tag` | slug тега (жанра) |
| `year` | ровно этот год, например `2001` |
| `year_from`, `year_to` | диапазон включительно (`2000`–`2010`), можно одну границу. С `year` вместе — 400 |
| `studio` | точное название студии (регистр не важен) — значение из подсказок ниже |
| `person`, `role` | **заглушка**: всегда 503 `person_filter_unavailable` (людей в индексе пока нет). `role` — `actor`, `director`, `producer`, `writer`, `composer`, ...; без `person` — 400 |
| `sort` | нет — по релевантности; `recommended`, `trending`, `top_rated`, `new` (только вышедшие, новые сверху), `soon` (только будущие), `title` |
| `limit`, `offset` | 1–100 (20), с 0 |

Ответ — `Page<EntitySummary>` `{items, total, limit, offset}`, `total` — оценка Meilisearch.
400 — неверный фильтр (`year_from > year_to`, год вне 1–9998, пустая студия, ...); 503 — поиск
недоступен.

Отличия от `/entities`: нет `popular` и `rating` (наших оценок нет в индексе) — на странице поиска
эти сортировки не показывать или переключаться на `/entities` только без `q` и новых фильтров.

### `GET /search/studios?q=warn&kind=movie&limit=10` — без авторизации

Подсказки для поля «Студия»: `[{"name": "Warner Bros. Pictures", "count": 123}]`. `q` — часть
названия, опечатки допустимы; пустой `q` — самые частые студии. `limit` 1–50 (10). `name`
передавать в `studio` как есть.

## Что сделать

1. `/films` (и другие типы): при `q` или любом из `year_from`, `year_to`, `studio`, `person`,
   `role` — грузить из `GET /search`, иначе можно оставить `/entities` (там есть `popular`/`rating`).
   Всё состояние — в адресе: `/films?q=…&year_from=2000&year_to=2010&studio=…`.
2. Панель фильтров: год — «ровно» или «от–до»; студия — комбобокс с подсказками
   (`/search/studios`, debounce); человек + роль — поля можно сделать, но при 503
   `person_filter_unavailable` показать «Фильтр по людям скоро появится», без общей ошибки.
3. `/search` (общий поиск) — те же фильтры; архив (`/archive/search`) — как раньше, вторым блоком.
4. `EntityPicker` — только `/search`.
5. `pnpm verify`.
