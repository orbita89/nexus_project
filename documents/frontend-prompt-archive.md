# Промпт для фронтенда: холодный архив каталога

Задача для сессии фронтенда (`/home/dev/nexus_web`). Бэкенд не менять: если в API чего-то не
хватает — записать в `docs/backend-questions.md`.

---

## Контекст

С 2026-10-14 каталог Nexus хранится в два уровня:

- **Горячий слой** — фильмы на сайте, как раньше: `entities` в PostgreSQL, карточки
  `/films/{slug}`, поиск `GET /api/v1/catalog/search` (Meilisearch). Это ~100 000 самых популярных
  фильмов (в основном с русским названием).
- **Холодный архив** — остальные ~1,09 млн фильмов TMDB. На сайте их **нет**: ни карточки, ни
  статики, ни места в `/entities` и `/search`. Хранится только «скелет»: slug, название,
  оригинальное название, тип, id TMDB, дата выхода, popularity. Искать — отдельным эндпоинтом.
  Админ может **вернуть** фильм из архива на сайт (промоушен).

Нужно: поиск по архиву на публичном сайте (как подсказка «нет на сайте») и раздел «Архив» в
админке с возвратом фильма на сайт.

## API

Все пути от `/api/v1/catalog`. Контракт — `documents/api/catalog.json` в репозитории бэкенда
(`operationId`: `archive_search`, `archive_promote`). Ошибки — `{"error": "...", "code": "..."}`.

### `GET /archive/search?q=...&limit=...` — без авторизации

- `q` — обязателен, 1–200 символов после обрезки пробелов. Ищутся **все** слова запроса в русском
  или оригинальном названии, без учёта регистра, без опечаток и стемминга («дюна» найдёт «Дюна»,
  «дюны» — нет; «ё» и «е» различаются). Выше — точнее совпавшие и популярные.
- `limit` — 1–20, по умолчанию 20. Пагинации и `total` **нет**: только топ.
- Фильтров по типу и году нет.

Ответ `200`:

```json
{
  "items": [
    {
      "slug": "the-night-visitor-1971",
      "title": "Ночной посетитель",
      "original_title": "The Night Visitor",
      "kind": "movie",
      "tmdb_id": 42491,
      "release_date": "1971-02-04",
      "popularity": 1.84
    }
  ]
}
```

`original_title`, `tmdb_id`, `release_date` могут быть `null`. `kind` сейчас всегда `movie`.
Постеров, описаний, жанров в архиве нет.

Ошибки: `400` (`code: validation`) — пустой или длинный `q`, `limit` вне 1–20; `503`
(`code: unavailable`) — архив не настроен или недоступен.

### `POST /admin/archive/promote/{slug}` — только роль `admin` (Bearer)

Возвращает фильм на сайт: создаёт сущность (`active: true`, `active_manual: true` — автоматическая
пересборка горячего слоя её не уберёт), удаляет документ из архива, обновляет поиск сайта и
статику (ISR). Тела запроса нет.

Ответ `201` — полная карточка `EntityDetail`, та же схема, что у `GET /entities/{slug}` (`id`,
`slug`, `title`, `original_title`, `release_date`, `kind`, `active`, ...). Карточка — «скелет»:
нет описания, постера, жанров, участников; их админ дописывает существующей формой
редактирования (`PATCH /admin/entities/{id}`).

Ошибки:

| Статус | `code` | Когда | Что показать |
|---|---|---|---|
| 401 | `unauthorized` | нет/истёк токен | обычный refresh и повтор |
| 403 | `forbidden` | не админ | кнопку не показывать не-админам |
| 404 | `not_found` | фильма уже нет в архиве (вернул другой админ) или неверный slug | «Фильма уже нет в архиве», убрать строку |
| 409 | `conflict` | `error`: `slug is already taken` / `tmdb id is already in the catalog` — фильм уже на сайте; `archive is being rebuilt, try again later` — идёт пересборка архива, в БД ничего не записано | для первых двух — «Уже есть на сайте» и ссылка `/films/{slug}`; для пересборки — «Архив пересобирается, попробуйте через несколько минут» |
| 503 | `unavailable` | архив недоступен | «Архив временно недоступен» |

Различать 409 — по полю `error` (тексты выше стабильны для этой версии API).

## Что сделать

### 1. Админка: раздел «Архив» (`/admin/archive`)

- Пункт меню админки «Архив» рядом с «Сущности».
- Строка поиска; запрос — с задержкой ~300 мс после ввода, пустая строка — подсказка
  «Введите название», а не запрос. Текущий `q` — в адресе (`?q=`), чтобы ссылкой можно было
  поделиться и вернуться назад.
- Таблица (до 20 строк): название, оригинальное название (если отличается), год из
  `release_date`, popularity (одна цифра после запятой), TMDB — ссылка
  `https://www.themoviedb.org/movie/{tmdb_id}` в новой вкладке.
- Подпись под таблицей: «Показаны 20 лучших совпадений — уточните запрос», когда пришло 20.
- В каждой строке кнопка **«Вернуть на сайт»** → подтверждение («Фильм появится на сайте без
  описания и постера — их можно добавить в редакторе») → `POST /admin/archive/promote/{slug}`.
  Пока запрос идёт — кнопка в состоянии загрузки, повторное нажатие заблокировано (запрос может
  идти несколько секунд: поиск и статика обновляются синхронно).
- Успех: строка исчезает из таблицы, тост «Фильм возвращён на сайт» со ссылками «Открыть» (`/films/{slug}`)
  и «Редактировать» (форма сущности по `id` из ответа).
- Ошибки — по таблице выше.

### 2. Админка: список сущностей

- В `GET /admin/entities` уже есть `active_manual`. Возвращённые из архива — с `active_manual: true`.
  Если в списке есть бейдж «вручную» — ничего делать не нужно; если нет — добавить бейдж в строку.

### 3. Публичный поиск: «нет на сайте»

- На странице поиска, когда основной поиск (`/search`) по запросу дал **0** результатов (или мало —
  меньше 3), показать блок «В архиве» с результатами `GET /archive/search?q=...&limit=5`.
- Элементы архива **не ссылки на карточку** (страниц у них нет): название, оригинальное название,
  год, пометка «Нет на сайте». Не рендерить их в SSR-разметку как ссылки на `/films/...` (будут 404).
- Ошибка или `503` архива — блок просто не показывать, основной поиск не ломать.
- Для админа (есть токен с ролью `admin`) в блоке — та же кнопка «Вернуть на сайт».

### 4. Не делать (в API этого пока нет)

Записать в `docs/backend-questions.md`, если понадобится в интерфейсе:

- отправить фильм с сайта в архив вручную;
- запустить пересборку горячего слоя и архива из админки (сейчас только CLI
  `nexus archive dump|build`), прогресс пересборки;
- число документов в архиве, фильтры по году/типу, пагинация поиска по архиву;
- данные TMDB (постер, описание) для строк архива.

## Проверка

- `pnpm verify` зелёный.
- Руками на dev (`make up` бэкенда, вход `admin` / `password123` или dev login):
  поиск в архиве «hamlet», «ночной», пустой ввод; возврат фильма → он открывается на
  `/films/{slug}`, повторный возврат того же → 404 и строка исчезает; поиск на сайте по названию,
  которого нет в горячем слое, показывает блок «В архиве» без ссылок.
- Состояния загрузки, пустого результата, ошибок 409/503 — видны и понятны.
